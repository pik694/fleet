# CLI: `fleet send` and the agent-facing control plane

- `fleet send <session> <message>` (`cmd/fleet/send.go`): messages a session from the shell — the half of a session's lifecycle the CLI couldn't reach. `<message>` is every argument after the selector, joined; a lone `-` reads stdin. Flags must come **before** the selector (unlike `fleet worktree`, whose flags parse on either side): a message is free-form prose that can start with a dash, and the flag parser silently eating words out of what the agent receives is worse than requiring flag-first. Delivery is `load-buffer` + `paste-buffer -p` + a **separate** `send-keys Enter` (`tmux.PasteAndSubmit`), not `SendLiteralKeys`: literal keys make every newline its own Enter, submitting a multi-line message a line at a time, and the Enter must land after the paste's closing bracket to read as "submit" rather than as pasted text. Selector tiers, most precise first: `@0`-`@9` slot, exact id, exact title, workspace name, git branch (injected as `branchOf` so the resolver stays pure — it's the only tier that shells out, hence last of the exact ones), id prefix, title substring. A tier matching several sessions is an **error listing them**, never a fall-through to a vaguer tier that happens to match one.
- `fleet send` guards, in order — each exists because the pane is a *typing* surface, not an API: **suspended** → wake it (`Restart()` with the message as `InitialPrompt`, then persist the new `tmux_session`, status **and any conversation id `adoptResolvedLaunchID` just healed** — the TUI's worker re-persists that a moment later, but a one-shot CLI process exits first and would recompute and discard the heal on every wake); **no tmux / `pane_dead`** → refuse; **pane back at a shell prompt** (`shell.IsShellCommand` over `tmux.PaneCurrentCommand`, after an explicit `RefreshSessionCache` since the TUI's tick isn't running) → refuse, because `/exit` or a crash drops the pane to a shell where the message *runs as a command* — deliberately **not** `-force`-able; **waiting** (`session.PaneIndicatesWaiting`) → refuse unless `-force`, since text typed into a numbered menu is discarded and its Enter confirms the highlighted option.
- `fleet send` startup handling — a session is launched by *typing* the agent's command into a fresh pane, so "not ready" and "exited" look alike from outside and the naive one-shot read got both wrong. Two separate waits, because one signal can't cover it: `waitForAgentInPane` polls up to `agentStartupGrace` (10s) for the pane to stop reading as a shell (measured process-start ranged **0.6s–7.4s**; under-waiting made `fleet wt … -p -` immediately followed by `fleet send` fail with a flatly false "has exited", and that branch isn't `-force`-able). That only proves the *process* started — the TUI then spends **~2.4s** painting, and anything written to the pty in that window is discarded. No signal distinguishes it: the process name has already flipped, and waiting for the pane to *settle* fires ~2s early (measured: settles at 783ms, input box renders at 2972ms) because the screen sits static mid-startup. So readiness is never predicted — `confirmDelivered` checks the **outcome**, polling the pane for the message's whitespace-squashed first line (or Claude's `[Pasted text` placeholder, since a multi-line paste is collapsed and never appears verbatim) and reporting an honest failure if it never lands. **No auto-retry** — a re-paste on a false negative submits twice. Costs ~65ms on a live session; a message under 6 chars skips the check, since a short needle would match by coincidence. That last check reads the **pane, not the hook**: granting a permission fires no hook, so the stored hook status stays `waiting` long after the user answered — stale in exactly the direction that would block legitimate messages. It returns false for OpenCode (no structural detector for its UI). Waking a suspended session prints a note that an already-open TUI picks the new tmux session up within a few seconds (see the relaunch bullet under external-session adoption).
- **Agent-facing control plane** (`fleet status` / `read` / `wait` / `answer` / `interrupt` / `submit` / `clear` / `restart` / `suspend` / `resume`): one-shot commands a supervising agent drives every session with, instead of `tmux capture-pane` and guessing. **Observation reinvents nothing** (`internal/control.Observer`): one `RefreshSessionCache` and one `BatchCapturePanes` for all sessions, then per session `FromRow` → the hook file into `UpdateHookStatus` → `UpdateStatus` — the TUI worker's own pipeline, read-only (nothing written to state.db; `session.DisableCrashDumps`, since every CLI invocation is a fresh "life" that would dump a dead session again). ~0.15s for 22 live sessions. Three gaps a one-shot observer has and the TUI doesn't, each closed with the TUI's *own* rules rather than a parallel one: (1) the stale-running-hook rule needs >10s of watched stable content, so on an observer's first look `SeedStableContent` primes that clock from tmux's `window_activity` — the fact the rule already defers to — **for a `running` hook only** (in the waiting path the same clock means "changed recently" and would flip a fresh prompt to running); (2) answering a prompt fires no hook, so a `waiting` status with no prompt structurally on screen is reported `running` — the pane-not-hook rule `fleet send`'s guard already follows (not for OpenCode, which has no pane detector); (3) an `Observer` is kept across polls by `fleet wait`, so multi-frame state accumulates exactly as on the worker. Status words: a pane back at a shell reads `exited`; an acknowledged session reads `idle` where state.db may still say `finished` (the TUI's `Acknowledge` flips memory without persisting status — the CLI matches the screen, not the column). Suspended sessions are counted, not listed, without `--all`. Output is compact text by default, **compact JSON** (`--json`, no indentation — a third of the tokens) for structure.
- `session.PaneView` (`paneview.go`) is what a *reader* needs, kept apart from the classifier. **Menus are parsed only when the agent's own waiting detector agrees** (`PaneIndicatesWaiting`), so a numbered list in prose is never a prompt; numbered rows first, then unnumbered `❯` rows (Copilot's boxed menus, Claude's folder-trust dialog) via `parseBoxedMenu`. Option rows read the **left column** only (the AskUserQuestion preview panel sits beside them), continuation lines go to `Detail` and stop at a side panel's indent or box edge. `Subject` is the dialog's first dashed (`╌`) frame — the exact Bash command or the diff — and Claude's `Tip:` banner is dropped from `Context`. Kind comes from the footer, with AskUserQuestion's "Esc to cancel"-only variant caught by its own rows (`Type something.`, `Chat about this`, a `☐` tab). **The input box separates a typed draft from Claude's prompt suggestion by ANSI alone**: both are the same characters, the suggestion is rendered dim (SGR 2), so `visibleRunesAllDim` tracks the attribute — skipping reverse-video (the block cursor sits on the first character) and consuming extended colours whole (a `38;5;2` colour index is not dim). Claude only; the creature animation past a 20-space margin is cut.
- `session.ReadClaudeTurns` reads a transcript's **tail** (256KB, doubling to 16MB until it holds one more prompt than asked) — transcripts run to hundreds of MB. A turn's `Reply` is the text after its **last tool call** (narration between tools is not the answer); `Done` from `turn_duration`, an interrupt, or the next prompt. Tool results are never decoded. The interrupt marker is matched **structurally** (`"text":"[Request interrupted by user`, unescaped quotes) *and* on a top-level `user` line: newer Claude Code writes `api-request-blob` lines replaying earlier messages, old interrupt markers included, which otherwise marked the running turn interrupted.
- Control verbs observe first, refuse anything that would type into the wrong place, act, then **check the pane for the outcome**. `answer` moves with arrow keys and **verifies the cursor landed on the asked option in the same prompt before pressing Enter** (Enter confirms whatever is highlighted); `--expect` refuses if the question no longer mentions what the caller read; multi-select and tab-focused prompts are refused. `interrupt` refuses a non-running session (Esc Esc on an idle Claude opens the rewind menu) and a prompt on screen (Esc there is "deny"). `clear` is `C-u` then (`BSpace`, `C-u`) per extra line, re-read between rounds — **never Esc** (interrupts a working agent; rewind on an empty box) **nor `C-c`** (clears, but arms "press again to exit"). `restart` respawns in place when tmux is up (the TUI keeps its pointer), full `Restart()` otherwise, and **refuses to resume a Claude conversation with no transcript** — Claude writes none until the first prompt, so `--resume` on a never-prompted session fails with "No conversation found" and drops the pane to a shell — unless `-fresh`. The guard checks `ResolveLaunchID`'s id, the one the relaunch actually resumes, not the transcript status reads (which falls back to the row's id). `-fresh` drops the id **in memory only**; `persistRelaunch` writes the empty id once the launch worked, so a failed one keeps the pointer to the old conversation. `restart`, `resume` and the `fleet send` wake **refuse a session pinned to a removed Claude account** (`accountGoneErr`): the launch would fall back to the ambient login and silently bill another subscription. The TUI's `healAccountBeforeRelaunch` re-picks instead, but where to move depends on quota and login state that live only in a running TUI, so the CLI names the fix rather than guessing; logged-out and spent pins fail visibly in the pane and aren't checked. `suspend` persists the conversation id the hooks reported **before** acting: with no TUI running nothing else has, and `Suspend` deletes the hook file it came from, so the next resume opened a new conversation (caught live). It also writes `suspended` to the row **before** the kill (restoring it if the kill fails), as `Suspend` marks memory first: an open TUI that sees the tmux session vanish reads the row, and one still naming a live state had it log a crash and persist `error` over the suspend. `remove` takes the shared selector minus the title-substring tier. Errors name the fix (`fleet restart <id>`), and `fleet send`'s now do too.
- `fleet wait` exit codes are interface: **0** reached (with `-until done`, finished cleanly), **2** timeout, **3** blocked on a prompt, **4** exited/errored; it returns early on 3/4 rather than sitting out the timeout, and prints the final reply. A state that already holds at the start counts only after `waitSettle` (3s), or once a hook in a **strictly later second** than the start lands (stamps are whole seconds, so a Stop from earlier in the send's own second would pass; `UserPromptSubmit` excluded), or once the session was seen not matching — so `fleet send …; fleet wait …` never returns before the agent picked the message up (`waitCounts`). A **`SessionStart`** latest hook counts only after settle: it maps to finished, and a launch or wake with a first prompt fires it just before that prompt's `UserPromptSubmit`, after the relaunch already showed running — otherwise `send -wait` on a suspended session returned the *previous* turn's reply. Rows are re-read every poll, so a session relaunched into a new tmux session mid-wait is followed rather than read as gone. `fleet send -wait` uses the send time as that boundary with a 20s fallback.
- Pipeline fixes the control plane surfaced, all in the shared status code: Claude's folder-trust dialog now reads **waiting** (its "Quick safety check" wording matched none of `approvalPatterns`; `Yes, I trust this folder` added); after a **denied** permission the session settles to finished instead of reading running for the whole 120s `conversationActiveWindow` — the deny's tool_result and interrupt lines are stamped after the waiting hook and read as the lead advancing, so `lastLeadTranscriptTimestamp` now also reports `turnEnded` when a `turn_duration`/`stop_hook_summary` follows the lead's last entry in file order (the timestamp itself is unchanged: bookkeeping still never moves it); and `StripANSI` decodes runes before matching the 8-bit CSI, since `0x9B` is also a UTF-8 continuation byte (`▛` U+259B) and was eaten along with the text after it.
