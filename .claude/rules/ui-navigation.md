# Keybindings, help sheet, context menu, palette, tips, delete

- Keybindings: j/k nav, `Shift+↑/↓` jump to prev/next group header (origin or checkout — from a session row the nearest header above is its own checkout header, so `Shift+↑` surfaces the current group before climbing out; clamps to the first/last row when no header remains, so it doubles as top/bottom), `Ctrl+Shift+↑/↓` the same motion one level up — origin headers only, so a repo with a dozen worktrees costs one press instead of a dozen (both share `nextRowMatching`, so the "own group first" landing, the edge clamp and the out-of-range guard can't drift apart; needs a terminal that sends `CSI 1;6A` for the chord — iTerm2/Ghostty/kitty/WezTerm/VS Code do, Apple Terminal does not), Enter attach, Space jump to next waiting/finished, `P` jump to the first session of the next checkout whose PR badge is red (CI failed / changes requested / unresolved threads / conflicts), else the next green one (approved + CI passed) — a collapsed checkout is expanded to reveal it, as Space does, and a checkout with no sessions lands on its header; the verdict is `prVerdict`, the same classifier `prBadgeStyle` paints from, so the jump can never land on a badge a different colour than it seeks; only checkout headers on screen are candidates (a collapsed origin hides its headers, muting it exactly as Space mutes its sessions; a collapsed checkout still shows its header), and snoozed checkouts — own deadline or origin umbrella — are skipped; drafts/merged/closed are never targets, and with PR badges turned off in Settings the jump is a no-op, since there is no badge to land on. **Not a Space chord, though that was asked for**: `Ctrl+Space` is macOS's "previous input source" shortcut on any Mac with two layouts, so the terminal never sees it, and `Shift+Space` arrives as a plain space — measured in Ghostty outside tmux (kitty flags=1, `"space"` for both) and through tmux — so it would silently fire Space's session jump instead; `Alt+Space` types U+00A0 unless the terminal sends Option as Meta. `P` pairs with `p` (open PR); like every uppercase command it is unreachable under caseless layouts (Hebrew/Arabic), where `Ctrl+K` → "Jump to Next PR Needing Attention" is the escape, a new session (instant, repo-scoped, default agent), A new session with agent picker (Claude/Codex/OpenCode/Copilot) + Claude account picker (`Auto` plus each account with its 5-hour quota; the row appears only with 2+ accounts and goes inert on a non-Claude agent), n new session (any repo, path autocomplete), w new worktree session (base branch + new branch; works on a session, checkout header, or origin header — an origin header bases the new worktree on the group's main clone), F fork to worktree (Claude-only), d delete (scope follows cursor: session = that session; worktree header = sessions + git worktree remove; repo header = forget repo from fleet, folder untouched; empty repo header = unpin; origin header = forget the whole group, checkbox-gated), u undo delete (5s window), r restart (confirm, configurable), R rename, m mark session as unread (idle→finished), z snooze (scope follows cursor; `z` again on a snoozed row wakes it), e editor, p open PR in browser, `Ctrl+P` copy PR link to the clipboard (same PR `p` resolves; copied via the `copy-command` tool — `pbcopy` / `wl-copy` / `xclip` / `xsel`; VS Code/Cursor's integrated terminal on Linux/Windows takes `Ctrl+P` for Quick Open before fleet sees it, so there `Ctrl+K` → "Copy PR Link" or the `.` menu is the escape — macOS is unaffected, Quick Open is `Cmd+P`), Y quick approve (waiting sessions), `.` context menu for the row under the cursor (session rows include "Move to Account…"), / filter, Ctrl+K command palette, `t` my tickets, `i` your stats (`w` inside it: weekly recap), `` ` `` toggle terminal drawer, S settings, X dismiss on-screen tip, ? help (sectioned + type-to-filter), ctrl+c quit
- Session hotkeys (RTS-style): `Alt+0-9` (or `=` then digit) binds the selected session to a slot; re-pressing `Alt+<N>` on a session already in slot N unbinds; `==` then digit clears any slot; plain `0-9` jumps to the bound session (double-tap within 400ms also attaches); `[N]` badge in sidebar marks bound sessions; bindings persist in SQLite `slot_bindings` table (FK cascade on session delete)
- Help sheet (`?`, `internal/ui/help.go`): 52 bindings grouped into sections (`KeyBinding.Section`, labelled by `helpSections`), **filterable by typing**. Two facts forced this: the `session` block is 23 entries, and every column was sized to the *single widest binding in the table* (`colW = keyW + 2 + descW` over all of them), so one 46-character description made two columns need ~130 terminal columns — at 80×24 the sheet was one column with 37 of 51 bindings off-screen, reachable only by `j`/`k`. Columns are now measured against **their own contents** (`newHelpChunk`), which is why the four slot bindings moved into their own `slots` section: they carried the two longest strings and were setting the width for every other key. The column count is chosen **height-first** (fewest columns that fit both budgets, falling back to the most that fit the width when nothing fits the height): a width-only search renders a two-hit filter as two one-row columns, which is what the pre-rewrite `colsByHeight` term existed to prevent. **Sections flow across column boundaries rather than pinning them** — packing whole sections into columns would floor the sheet at the height of `session` (23 rows) and make 100×30 *worse* than before; a section split across a boundary repeats its header as `… (cont.)`. Typing breaks the old "press any key to close" contract deliberately, and with it `j`/`k`/`g`/`G` as scroll keys (scrolling is arrows / PgUp / PgDn / Home / End; `esc` clears a filter before it closes the sheet, so one press never discards both). **The `⋮ +N above/below` scroll notes ride the separator rows the frame already has** (the blank under the filter and the blank above the hint), so scrolling reserves no rows of its own — overflowing by k rows hides exactly k, and the frame is identical whether or not the sheet scrolls. A version that added two indicator rows on overflow turned the one row the `P` binding added into three hidden bindings at 120×40 (`TestHelpSheetHoldsTwoColumnsAt120` pins both budgets: whole at 120×41, exactly one row over at 120×40). Headers drop while filtering, following the palette's rationale, and the section folds onto the row instead — **load-bearing, not decorative**: `` ` ``, `Enter` and `PgUp/PgDn` each appear in two sections meaning different things, so a filtered list without the tag shows one key contradicting itself. `routeToModal` hands this overlay the **raw** key, not the `normalizeKey`-remapped one, or a Hebrew user's search box would silently type Latin — which also moves it out of `TestNormalizedDialogsHoldNoTextInput`'s scan set, so `TestNonLatinTypingReachesTheHelpFilter` guards that direction instead.
- Context menu (`.`): a dropdown anchored to the sidebar row under the cursor (`internal/ui/context_menu.go`), listing the actions valid for that row kind — session / checkout header / origin header, seeded from the existing `cursorBarContext()` classifier. **It adds no behavior of its own**: each entry carries a `dispatchCommand` action id (`buildContextMenuItems` in `app.go`), so handlers and action-log entries are inherited from the command palette's dispatcher. Three ids were added for it: `delete_at_cursor` (→ `deleteAtCursor()`, the scope-follows-cursor delete the `d` key now shares), `toggle_group`, and `resume` (a suspended row can't `attach` — its tmux is gone). Actions that exist but can't run *right now* render **dimmed with the reason** and are skipped by `j`/`k`. Every such guard is a conjunction, so the note **switches on which clause failed** — a Claude session with no resume id yet says `no session id yet`, not `Claude only`; a waiting session whose pane died says `session not running`, not `not waiting`. A constant note there is a bug: it contradicts the status dot rendered next to it. The guards mirror the real handlers exactly, so a lit row can never dead-click. Each row shows its keybinding and **pressing that key inside the menu fires it**, making the menu a discovery surface that trains users onto the faster path — so a row's shortcut must be the key that *actually* works: `resume` is pinned to a literal `⏎` because `handleKey`'s suspended check runs above the split-mode Enter↔Tab swap, so Enter resumes in both modes. Renders via the palette's overlay pattern (`View()` returns a bare box, composited with `overlayAt`) but **without `dimBackdrop`** — it's a small box beside its row, not a modal takeover. Anchored by `contextMenuAnchor()` (sidebar content starts at y=2 in every layout: header row + panel border; +1 more when `viewOffset > 0` adds the "… N more above" row); hangs below the row and flips above near the footer.
- Context menu target (`contextMenuTarget` in `app.go`): the menu's entries all resolve their subject from `h.cursor` at dispatch time, so **the cursor must still be on the row the menu named**. Keys can't move it (`routeToModal` feeds them to the menu) but **messages can** — `handleSessionCreate` and the workspace-create handler both auto-select the row they just made, and `rebuildFlatItems` runs on the tick. Since workspace creation is non-blocking by design, a session finishing while the menu is open would slide the cursor onto a different row and `d` would confirm deleting a session the menu never named. So `.` captures the row's identity (`targetForCursor`) and the `contextMenuMsg` handler re-finds it (`focusContextMenuTarget`) before dispatching, refusing if the row is gone. Two guard tests: `TestContextMenuIDsAreDispatchable` parses `dispatchCommand`'s case literals and fails if a menu id isn't handled (the dispatcher no-ops silently on unknown ids, so a rename would otherwise turn an entry into a dead click), and `TestContextMenuDispatchFollowsTargetNotCursor` moves the cursor under an open menu and asserts the action still hits the original row.
- Command palette (Ctrl+K): renders as an overlay over the sidebar/preview (not a full-screen takeover); fuzzy-searches commands plus every repo/worktree currently in the sidebar (name, branch, full path all matched); picking a repo/worktree jumps the sidebar cursor to that header (auto-expand if collapsed); palette-only commands include "Reload All Sessions" (restarts all dead/error sessions). For a native Cmd+K feel on macOS, map Cmd+K → Ctrl+K in your terminal prefs (iTerm2: Profiles → Keys → Key Mappings → +; Ghostty: `keybind = cmd+k=text:\x0b`).
- Contextual tips: a bottom-right hint box surfaces actionable tips when a condition holds (catalog in `internal/ui/tips.go` → `tipRegistry`). Two policies: `tipRecurring` (condition-driven, e.g. ≥4 error sessions → "Reload All Sessions" hint; dismissal is in-memory and the tip recurs when the condition repeats) and `tipOnce` (no recurrence, e.g. command-palette discovery; auto-expires after `tipOnceBudget` and is persisted in config `seen_tips`). A teaching `tipOnce` may also set `LearnedKey`: once the user has invoked that feature `tipLearnedThreshold` (5) times — counted in config `feature_usage` via `Config.NoteFeatureUsed`, bumped at the feature's call site (e.g. `Ctrl+K`, drawer open) — the tip retires for good even if never seen/dismissed (`tipLearned` gate in `refreshTips`). `refreshTips` runs on the ~2s tick; `Shift+X` (`dismissActiveTip`) hides the visible tip; rendered via `renderTip` + bottom-right overlay (stacked above any toast), suppressed while a modal is open (`modalOpen`)
- Undo delete: `u` key restores last deleted session within 5s window (stacked — multiple deletes each undoable). Tmux kept alive during window for full restore.
- Pinned repos: repos auto-pinned on session creation, persist in SQLite. Empty repos show dimmed with "(empty)". `d` on empty repo header unpins it.
- Delete scope follows the cursor (single-purpose `y`/`n` confirm, no extra buttons): `d` on a session deletes only that session; `d` on a worktree header deletes its sessions + runs `git worktree remove` + unpins; `d` on a real-repo header "forgets" the repo (deletes its sessions + unpins, folder untouched); `d` on an empty real-repo header unpins instantly (no dialog). Worktree-vs-repo detected via cached `RepoInfo.IsWorktreeRepo`, falling back to a direct `git.IsWorktree` check for empty headers the worker hasn't cached yet. Header deletes route through the same deferred-delete machinery, so `u` undo works (LIFO, per-session).
- Origin-row delete (`d` on the top-level origin header): forgets the **whole group** — every checkout under the origin (main repo + all worktrees) and their sessions. Because it wipes a group at once, the confirm dialog is **checkbox-gated** (`ConfirmDialog.RequireCheckbox` — `space` toggles `◉`, `y`/`Enter` inert until ticked). `confirmDeleteOrigin` gathers checkouts via `checkoutsForOrigin` (scans sessions + pinned + pending, deduped — works even when the origin is collapsed) and fans out to `deferDeleteRepo` per checkout, so each follows its own rule and `u`-undo still works. Whether worktree dirs are also removed from disk follows the `origin_delete_removes_worktrees` config (default true; main repo folder always kept).
