# CLI: `fleet worktree`, `fleet add`, launch flags

- `fleet worktree <branch>` (alias `wt`, `cmd/fleet/worktree.go`): the TUI's `w` key as a CLI command — create the worktree, copy `.claude/settings.local.json` + `copy_files` entries, start a session. Flags: `--base` (defaults to `git.GetDefaultBranch`), `--path` (defaults to cwd), `--agent` (defaults to `default_agent`; **validated explicitly** — `agent.Parse` falls back to Claude for anything unrecognized, so a typo would silently launch the wrong agent), `--account` (Claude account email; defaults to whatever `account_strategy` picks. **Validated explicitly against the configured accounts** — an unknown name errors rather than falling back, since the cost of a typo here is billing the wrong subscription. Rejected alongside a non-Claude `--agent`, which would silently ignore it), `--no-session` (print only the worktree path, so `cd "$(fleet worktree foo --no-session)"` composes; conflicts with `--agent`, `--account` and `--prompt`), `--prompt`/`-p` (the agent's first message — `-p -` reads stdin, so `gh issue view 242 | fleet wt fix-242 -p -` works; conflicts with `--no-session`). An explicitly **empty** `-p` is rejected rather than ignored: `-p "$(gh issue view 999)"` on a missing issue expands to nothing, and silently starting a promptless session reads as a broken flag (`fs.Visit` is what separates `-p ''` from an absent `-p`). Flags parse on **either side** of the branch (a loop peeling one positional per `fs.Parse` — a single Parse stops at the first positional and would reject `fleet worktree foo --no-session`). It resolves to the **main** worktree (`git.GetMainWorktreePath`) before creating, so running it from inside `repo-foo` yields `repo-bar`, not `repo-foo-bar` — same as pressing `w` on an origin header. It calls `debuglog.Init()` first: `debuglog.Logger`'s fallback writes to **stderr**, and the provider/`Session.Start` log at Info, so without it the command spews slog lines over the user's terminal (`fleet add` now does the same).
- Initial prompt (`Session.InitialPrompt`, set by `fleet worktree -p`, `fleet add -p`, and by `fleet send` waking a suspended session): the agent opens **already working on it**, because every agent takes a first message on its own command line (`claude "<p>"`, `codex "<p>"`, `opencode --prompt "<p>"`, `copilot --interactive="<p>"`, each also valid alongside resume/fork). The text never enters that command string. `tmux.Session.Start` *types* the launch command into the pane's shell, so an embedded prompt would be parsed by that shell — `$(...)` and backticks would execute, and a newline would end the command early. Instead the prompt rides `tmux new-session -e FLEET_INITIAL_PROMPT=<raw>` (`agent.PromptEnvVar`, set in `sessionEnv`), which no shell parses, and the command carries only `"$FLEET_INITIAL_PROMPT"` — one argv element whatever it contains. Two tests pin this: `TestBuildLaunchCmdNeverEmbedsPromptText` and `TestInitialPromptTravelsInEnvNotCommand`. Quoting only settles the **shell**; the agent's own argv parser is a second parser, and it reads a leading `-` as an option and *exits* — leaving a live session at a shell prompt with the message gone. So the prompt sits behind a separator that ends option parsing: `-- "$FLEET_INITIAL_PROMPT"` for Claude/Codex, `--prompt="$FLEET_INITIAL_PROMPT"` for OpenCode, `--interactive="$FLEET_INITIAL_PROMPT"` for Copilot (with a space, yargs reads the *value* as a fresh option). `fleet send` explicitly promises a message may start with a dash, and the suspended-wake path routes that message through here. **One-shot**: every launch path clears it on success via `consumeLaunchOverridesLocked` (which also clears the launch model/effort — see the next bullet) — `Start`, `Restart` (the `r` key, and the idle-suspend wake) and `RespawnClaude` all build from `buildAgentCmd` + `sessionEnv`, so a path that forgets silently re-asks the original task. Never persisted, or it would replay on every app restart. Kept on a *failed* launch so a retry still carries it.
- `fleet add [path]` (`cmd/fleet/add.go`): a session in a directory that already exists — no worktree, no branch. Takes the same session-shaping flags as `fleet worktree` (`-p`/`--prompt` including `-p -`, `--agent`, `--account`, `--model`, `--effort`), parsed with the same either-side peel loop, since a path is not free-form prose. The path is **optional** (defaults to cwd, like `fleet worktree --path`) but a **bare `fleet add` with no arguments stays a usage error**: it was one before, and a mistyped `fleet add` in the wrong tab would otherwise launch an agent wherever that tab happened to be. A `-p` prompt **titles the session** via `naming.GenerateTitle`, setting `TitleGenerated` exactly as the TUI's own fallback does — the agent's own title still overrides it later (that path checks only `ManuallyRenamed`), while the worker stops regenerating an identical title from `FirstPrompt`. It calls `migration.Run()` *and* `debuglog.Init()` before `session.Open`, both of which it previously skipped: `session.Open` creates `state.db`, after which `migrateConfigDir` permanently bails out ("both dirs have state.db") and still writes its marker, silently stranding a `brizz-code` user's sessions, pins and slot bindings if `fleet add` was their first fleet command.
- **`cmd/fleet/session_launch.go` owns what `fleet add` and `fleet worktree` do identically** once they know where the session goes: `resolveLaunchAgent` (flag → `default_agent`, plus the PATH check), `resolveLaunchAccount` (the per-origin allowlist, explicit-account validation, `claudeaccount.Select`, the `AllowedConfigured` split, the all-logged-out note, `GuardConflictingAuth`), `installAgentHooks`, and `launchSession` (hooks → fields → `Start` → `SaveSession` → `PinRepo`). It exists because the two had **drifted**: `fleet add` carried a shorter copy of the account logic with no explicit-account branch, no note when the strategy couldn't rank, and `GuardConflictingAuth` called from inside the wrong branch — a second, weaker implementation of a policy whose whole point is that a mistake bills the wrong subscription. It also never installed hooks at all, so a CLI-created session had no status detection, and a failed `SaveSession` left an orphaned live tmux pane nothing pointed at. These helpers **exit the process** rather than returning errors — the shape of the code they were lifted from, kept so the move reads as a move; the cost is that the policy stays untestable and only review catches a change to it.
- Launch overrides — `--model` and `--effort` (`Session.Model`/`Session.Effort` → `agent.LaunchOpts`), on both `fleet add` and `fleet worktree`. **One-shot on exactly InitialPrompt's terms**, cleared by the same call (`consumeLaunchOverridesLocked`, renamed from `consumeInitialPromptLocked` when it widened), and **never persisted** — that is a decision, not an omission: the agents treat these as session-scoped (Claude documents `--effort` as non-persistent; Codex's `/model` popup writes its own config) and all of them let the user change model mid-session, so a value fleet stored would be re-imposed on the next restart and silently undo that choice. Unlike the prompt they ride **in** the command string, which `tmux send-keys` types into the pane's *shell*, so a value carrying `;`, a backtick or `$(...)` would be executed — `agent.ValidateLaunchValue` rejects anything outside `^[A-Za-z0-9][A-Za-z0-9._/-]*$` at **parse time**, before anything is created, and both commands call that one copy. The charset is sized against real values (`opus`, `claude-opus-5`, `gpt-5.1-codex-max`, `anthropic/claude-sonnet-5`, `high`, `xhigh`, `ultracode`); model ids change too fast for an allowlist, so shape is the check and the agent rejects an unknown name itself. `--model` is `--model` for every agent and is passed through untranslated (each takes its own spelling). **Effort is two spellings and one agent that has none**, which `internal/agent` absorbs: `--effort` for Claude, `--reasoning-effort` for Copilot (which, unlike Claude, *exits* on a value outside `none|minimal|low|medium|high|xhigh|max`, so `guardEffortSupported` refuses one at parse time via `agent.ValidEffort`), `-c model_reasoning_effort=<v>` for Codex (whose value needs no quoting — `-c` parses it as TOML and falls back to the raw string, so a bare `high` survives the shell), and **nothing for OpenCode**. OpenCode *has* the concept, spelled `--variant`, and fleet shipped that spelling for exactly as long as it took a reviewer to run the binary: the option is declared on the **`run` subcommand**, while fleet launches the *default* command (`$0 [project]`), whose builder declares only `project`, `prompt` and the network options — and OpenCode's root parser is **yargs in `.strict()` mode**, so an unknown option is not ignored, it prints the command list and *exits*. That would have produced a session fleet reports as created, with its row saved and its repo pinned, whose pane is a shell prompt with no agent — the failure `promptArg` describes, which nothing in fleet detects at launch. So `agent.SupportsEffort` is false for OpenCode and `--effort` is **refused** there rather than dropped, at parse time when `--agent` says so and again in `guardEffortSupported` once `default_agent` is resolved (the same two-place check `--account` needs, and for the same reason: the parse-time guard can't see `default_agent`). `BuildLaunchCmd` re-checks as well, so a caller that forgets drops the flag instead of launching a command the agent refuses. `--model` is unaffected — the default command's handler reads `args.model`. Both are appended **ahead of the prompt argument**, since `--` ends option parsing and anything after it stops being read as a flag (`TestModelAndEffortPrecedeThePrompt`). Refused with `--no-session`, like `-p`/`--agent`/`--account`.
