# Worktrees, `.fleet.json`, base-branch fetch, worktree removal

- Worktree removal kills holding processes: leftover dev daemons (process-compose, air, vite/node) that detached from the tmux pane pin the worktree dir and make `git worktree remove` fail with "Directory not empty". Before removing, `destroyWorktree` (app.go) finds holders via `internal/proc` (platform-split discovery: `lsof -Fpcn` on macOS in `proc_darwin.go`, a native `/proc/<pid>/{cwd,exe,fd}` walk on Linux in `proc_linux.go`; shared prefix-match + kill policy) and SIGTERM→grace→SIGKILLs them — sparing a denylist (editors, language servers, shells, tmux, fleet, ssh). `GitWorktreeProvider.Destroy` falls back to `os.RemoveAll` + `git worktree prune` (package mutex serializes concurrent removes). The delete dialog pre-lists warnings: uncommitted-changes, running-session count (instant from cache), and an async "Will terminate N process(es): …" line (`ConfirmDialog.StartScan`/`SetScan`, gen-guarded). If removal still fails, the worktree is re-pinned + flagged `✕ removal failed — d to retry` (`failedWorktreeRemovals`), so `d` retries.
- Workspace: built-in git worktree support (zero config), per-repo `.fleet.json` (or legacy `.bc.json`) overrides with custom shell commands
- Workspace creation is non-blocking: dialog closes immediately, phantom "Creating..." entry with spinner appears in sidebar, user can keep navigating
- Worktree creation copies `.claude/settings.local.json` from source repo (configurable via `copy_claude_settings`, default true)
- Base-branch fetch before worktree creation (`git.FetchBaseRef`): `git worktree add -b <new> origin/master` resolves `origin/master` **out of the local clone and never asks the remote**, so a worktree could start days behind and need a merge as its first act. Both create paths — the `w` dialog's async closure and `fleet worktree` — refresh that one ref first. The refspec-less `origin <branch>` form is deliberate: it is what opportunistically updates `refs/remotes/origin/<branch>`, the ref `worktree add` then resolves — behind a `--` terminator, because git's parser takes options *after* a positional, so a base of `origin/--upload-pack=/tmp/x` would otherwise reach `--upload-pack` and run it (reproduced; git refuses to *create* such a branch, so it can only come from someone typing it, but the terminator is one token). `--no-write-fetch-head` because FETCH_HEAD is the user's and a manual `git merge FETCH_HEAD` must not merge fleet's fetch (it costs the feature on git <2.29, the safer of the two failures); `-c gc.auto=0 -c maintenance.auto=false` because a fetch normally signs off by kicking automatic housekeeping, which on a large repo is a repack competing with the agent sessions already running. Only an **`origin/`-prefixed** base is fetched — the only form fleet produces — since splitting a bare name on `/` would read a local `feature/foo` as remote `feature` and spend the whole budget on a fetch that cannot work. **Advisory, exactly like the file copies beside it**, and the budget is two mechanisms rather than one: `fetchTimeout` 5s (deliberately under the 8s `gitTimeout` — offline it can only ever fail, so the budget is what an offline user should wait) **plus `cmd.WaitDelay`**, without which the timeout does not bound anything. `CommandContext` kills git on expiry, but `CombinedOutput`'s `Wait` then blocks until every holder of the pipe's write end exits, and a fetch over SSH hands that end to an `ssh` grandchild the kill never reaches — **measured at 30s against a 1s budget**, with the `Creating…` phantom spinning the whole time (`TestFetchBaseRefReturnsWhenAChildLeaksThePipe`, which needs a full second of budget: a shorter one kills the fake before it spawns the grandchild and then passes against the unfixed code). `GIT_TERMINAL_PROMPT=0` governs git's own prompts and not ssh's, which reads `/dev/tty` directly and would print over the TUI, so `GIT_SSH_COMMAND=ssh -o BatchMode=yes` is set too — **only when the caller defines none**, since overriding one carrying an identity turns a working fetch into a silently failing one; a `core.sshCommand` in config is the residual gap, and `WaitDelay` bounds it. Any failure branches from the refs already there. It runs **after** the dialog closes, inside the `Creating…` phantom's window, where a ~2s round trip is invisible — at dialog-open time it would either hold the box shut for it or move the base-branch suggestion rows under the cursor when it landed. Deliberately **not periodic**: measured across 10 origin groups here, the repos worktrees are actually cut from were already current (agent sessions fetch as part of the work), so a background sweep would spend ~2s per group forever to refresh what is already fresh. Skipped when the branch already exists, on **both** paths (`git.BranchExists`, promoted out of `cmd/fleet`): `Create` retries without `-b`, which drops the base, so the fetch would refresh a ref `worktree add` never reads. `F` (fork) is untouched — it branches from the session's HEAD, not from origin. `GetDefaultBranch`'s fallback had to change with it: `git init` + `git remote add` writes no `refs/remotes/origin/HEAD`, so it returned a bare local `main`/`master`, which both contradicts its own contract and misses this gate — it now prefers `origin/<name>` when that ref verifies, leaving the bare name only for a repo with no remote copy at all.
- `.fleet.json` / `.fleet.local.json` in repo root (legacy `.bc.json` / `.bc.local.json` still read): `{"workspace": {"list": "cmd", "create": "cmd {{name}} {{branch}}", "destroy": "cmd {{name}}"}}`
- `.fleet.json` / `.fleet.local.json` may also set `{"pr_checks": {"ignore": ["glob", ...]}}` to drop matching CI checks from the PR-badge rollup (path.Match globs; lists from both files merge additively; opt-in, empty by default)
- `.fleet.json` / `.fleet.local.json` may also set `{"copy_files": {"paths": ["path", "dir", "glob/*", ...]}}` to copy gitignored files/dirs/globs from the source repo into each new worktree (filepath.Glob semantics, repo-relative only; lists from both files merge additively; opt-in, empty by default; applies to both git-worktree and shell providers; independent of `copy_claude_settings`)
- Trust for `.fleet.json` shell commands (`internal/workspace/trust.go`): a repo's `workspace.list/create/destroy` commands are handed to `sh -c`, so a cloned repo could run anything the first time you pressed `w`. `ShellProvider.List/Create/Destroy` now return `ErrUntrustedCommands` unless the provider's **own** commands match the fingerprint recorded for the repo — the chokepoint, so no call site can forget, and a provider built from a config that changed after it was read is refused too. Trust lives in `~/.config/fleet/trusted_commands.json` (0600) as main-checkout path → SHA-256 of the three merged commands, so it is **lost whenever the commands change** (a pull, a branch switch, an edit to `.fleet.local.json`) and a linked worktree with identical commands is not asked again. The main checkout is resolved by reading the `.git` pointer and `commondir` files, never by forking git: `CommandsTrusted` is called from the Update goroutine (`confirmDeleteHeader`). Untrusted means **refuse, never fall back** to the git provider — a repo with its own tooling would get worktrees made a different way with nothing saying so. TUI: `fetchWorkspaceListForRepo` checks trust before anything else (a create-only config would otherwise fail on "list command not configured" first) and the `workspaceListMsg` handler opens a `ConfirmDialog` listing every command in full (`askToTrustCommands`); `d` on a worktree header asks the same instead of offering removal. Accepting records trust and toasts "repeat the action" rather than replaying it — the prompt answers "may these run", not "run this now". CLI: `fleet worktree` prints the commands and exits 1 before creating anything; `fleet trust [path]` records trust and **never prompts**, so the decision is an explicit command rather than a `y` an agent driving a terminal could type. Session and origin deletes that reach `destroyWorktree` untrusted fail through the existing `✕ removal failed — d to retry` path, and that `d` is what prompts.
