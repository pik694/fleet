# `fleet skill` and the embedded SKILL.md

- `fleet skill <install|uninstall|status>` (`cmd/fleet/skill.go`, `internal/skill`): installs the [Agent Skills](https://agentskills.io) `SKILL.md` that teaches a coding agent to drive fleet's CLI. **Opt-in, unlike hook injection** — hooks are load-bearing (no status without them), a skill is a convenience, and it costs its description in the context of *every* session in every repo, so it stays the user's call. Discovery is `fleet -h` (worded at agents: "run `fleet skill install` yourself, it never prompts") plus a `tipOnce` in the TUI. **Never prompts and never reads stdin**, so an agent can install it for itself in one call. Writes **two roots, not four**, because the agents overlap: `~/.claude/skills` (Claude Code; also read by OpenCode and Cursor) and `~/.agents/skills` (Codex, Cursor, OpenCode, and Copilot — which reads `~/.copilot/skills` or `~/.agents/skills` and is detected by binary only, since the VS Code Copilot extension creates `~/.copilot` without the CLI). Neither root alone suffices — Codex reads only `.agents/skills`, Claude Code only `.claude/skills` — and Cursor/OpenCode map to `.agents/skills` so either one installed *without* Claude Code still lands somewhere it reads. Agents sharing a root share one write (`run` dedupes by path), so three selected agents don't race three writes at one file. **Selection is by name, the operation is by path, and the report must follow the path** — `run` acts in a first pass and reports in a second, so an agent the user *didn't* select whose file was written or deleted anyway (because a selected agent shares its root) reports what really happened, tagged `SharedWith` and rendered `(shared with codex)`. Reporting it as skipped told an OpenCode user their skill was untouched in the same breath as deleting it. Read-only `Status` deliberately does **not** disclose sharing: nothing changed, so there's no side effect to own up to, and disclosing it would make an explicit `-agent` filter look ignored. Frontmatter is restricted to **`name` + `description`**: that's the intersection every target accepts (Claude Code's packaging validator rejects unknown keys outright), and `name` must equal the install directory or the skill silently never loads — `TestFrontmatterIsPortable` pins both. Written via temp-file + rename because **Claude Code watches skill dirs for live changes**, so a partial `SKILL.md` can be read mid-write. Install defaults to **detected** agents; uninstall and status default to **all** (the copy worth removing or finding usually belongs to an agent the user has since uninstalled), and every verb honours `-agent` — `status` silently dropping a valid filter would be the same swallowing `resolveAgents` rejects for typos. Detection is binary-on-PATH, plus a config dir **only where fleet never creates one**: `~/.cursor` counts (Cursor installs its `cursor` shim only on request), `~/.codex` and `~/.config/opencode` count (their injections are `LookPath`-gated for exactly this reason), and **`~/.claude` explicitly does not** — `NewHome` calls `InjectClaudeHooks` ungated and it `MkdirAll`s the dir, so every fleet user has one whether or not Claude Code exists. Trusting it installed a Claude skill for Codex-only users. A skipped agent's printed reason re-checks detection rather than assuming: telling a Cursor user Cursor isn't installed, when they merely passed `-agent claude`, is a false claim about their machine. The TUI's tip samples `skill.AnyInstalled()` **once in `NewHome`**, not from the tip's `active()` — that runs on the ~2s Update tick, where filesystem calls don't belong.
